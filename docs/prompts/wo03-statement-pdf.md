# WO-03: PDF export for the Statement tab

Same worktree and branch as WO-03 (fast-forward to `main` first); no new branch; commit, push, keep an open PR with the latest push. Target: merged Saturday 10 Oct before the 23:59 freeze, so it is small and exact. Behind the existing statement flag; nothing else changes.

## Build
A "Download statement PDF" button next to the existing "Download statement CSV" (`apps/web/components/portfolio/statement-vm.tsx`), generated **in the browser from the same statement view model the CSV uses** (the numbers must be identical to the CSV and the screen; never recompute with floats; shares and USDT are strings or bigint as in the VM). File name like the CSV's: `tally-statement-<wallet first 6>-<UTC date>.pdf`.

**Library:** `jspdf` (MIT) is approved as the one new dependency in `apps/web/package.json` (add it with `pnpm add jspdf --filter @tally/web` so the lockfile is updated and CI's frozen install passes). Load it with a dynamic `import()` on click only, so it adds nothing to the page's first load.

**Contents (A4, black text on white, Helvetica; no images needed):**
- Title "Tally statement", the wallet address (full, monospace), the period or "all recorded activity" as the CSV states it, and "Generated <UTC date and time>".
- The same sections and rows as the CSV, in shares (token, issuer, shares, cost or proceeds where known, realized only where known, "unknown" where the data is unknown; never a made-up number). Repeat the column header on every page; break rows cleanly across pages.
- A short note at the end: "Tokenized shares track a US stock's price; they are not the underlying shares. This statement is a record of onchain activity, not tax advice." If the data is fixture data, the first page says "Fixture data, not live" prominently.
- **First page, bottom right corner, small grey-black text (about 8 pt), exactly: `Generated by` + the Tally mark + the word `Tally`.** The mark is drawn with three filled black rectangles (no image): a horizontal bar over two vertical bars, the geometry of `apps/web/public/logo.svg` scaled to about 8 pt tall. **`Tally` is a real clickable link** (`doc.textWithLink` or a link annotation over the word, and also over the mark) to `https://tallyprotocol.xyz`; put that URL in one constant (`TALLY_HOME_URL`) next to the PDF code. The line appears on the first page only, kept inside the page margin so it is never clipped.

## Tests
A pure builder (statement VM in, a document description out) with unit tests (rows equal the CSV rows; page breaks; fixture label; empty statement says so plainly). A Node test that generates the PDF with compression off and checks: it starts with `%PDF`, contains the string `Generated by`, and contains a `/URI (https://tallyprotocol.xyz` link annotation exactly once. A Playwright test on the fixture server: click the button, a `.pdf` download with the right name arrives, the CSV button still works, and the page has no horizontal scroll at 375 px. If the PDF cannot be built (library failed to load), show a plain message; never a blank file.
