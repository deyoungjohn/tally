## What it shows
For one ticker, side by side per issuer: how many more shares one token now represents than at the start of the history (multiplier growth), and the dividend the API reports (`latestDividend`, `dividendYield`). Ondo pays dividends by raising the multiplier (more shares per token); bStock and xStocks report them separately. The point: the user sees which issuer actually passed dividends through. Say what the data supports and no more: no USD "total return" claim (there is no price history here), no claim that the two numbers must match, and every figure carries its date.

## Data
1. **History store.** New snapshot kind `multiplier-history` (key `<token address lowercase>`), one point per token per UTC day, `{ multiplier: string (1e18), source: "api" | "onchain" | "seed", observedAt }`. Written by the existing `statement` worker job (apps/worker/src/jobs/statement.ts), from the registry snapshot it already reads (`tokenToShareRatio`/the multiplier the engine resolved); no new API calls for this part. Add the kind to the prune allowlist in `apps/worker/src/jobs/prune.ts` with 120 days of retention (the prune file is Agent 04's; this one allowlist line is approved, keep it a one-line change plus its test).
2. **Seed.** Backfill with real points from the two committed research snapshots, `research/snapshot-2026-09-30/` and `research/snapshot-2026-10-02/` (and `data/ondo-multiplier-baseline.json`): write a small offline script `packages/mod-statement/scripts/seed-multiplier-history.ts` that produces the committed `data/multiplier-history-seed.json` (token address, symbol, issuer, points with `source: "seed"`). The loader merges the seed with the store, store wins on the same day. Seeds must be labelled "recorded 30 Sep and 2 Oct" in the VM, never as live.
3. **Dividends.** `latestDividend` and `dividendYield` come from the authenticated `/market/rwa/underlying-market` (see `packages/binance/src/schemas.ts`, `trading.ts`). Add to the same `statement` job a budgeted read: only the registry tokens that are buyable (the generated list in `apps/web/lib/buyable.generated.ts`, about 30 tokens) and held tokens, at most one call every 2 seconds, refreshed every 6 hours, stored as snapshot kind `dividend-info` (also allowlisted in prune, 7 days). If a call fails or the field is null, store "unavailable" with the reason; never fill it. Fixture mode uses the recordings in `spike/results/module_probes_*.json` (they contain `latestDividend`).
